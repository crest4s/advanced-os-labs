1. ¿De qué tipo es una variable que contiene un descriptor de fichero?
   -------------------------------------------------------------------
   
   RESPUESTA: int
   
   Los descriptores de fichero son enteros no negativos (int) que el sistema 
   operativo asigna a cada archivo abierto. Son índices en la tabla de archivos 
   abiertos del proceso.
   
   Ejemplo:
   int fd = open("archivo.txt", O_RDONLY);


2. Sea la siguiente invocación: lseek(fd, 0, SEEK_END). ¿Dónde se posiciona 
   el puntero de acceso al fichero?
   ----------------------------------------------------------------------
   
   RESPUESTA: Al final del fichero
   
   SEEK_END indica que el desplazamiento se aplica desde el final del archivo.
   Con desplazamiento 0, se posiciona exactamente al final (después del último byte).
   
   Usos comunes:
   - Obtener el tamaño del archivo (el valor retornado es el tamaño)
   - Preparar para añadir datos al final del archivo
   
   Ejemplo:
   off_t size = lseek(fd, 0, SEEK_END);  // Retorna el tamaño


3. Dada la declaración:
   char buffer[100];
   read(fd, buffer, sizeof(buffer));
   ¿Cuántos caracteres se leerían del fichero?
   --------------------------------------------
   
   RESPUESTA: Hasta 100 bytes (caracteres)
   
   sizeof(buffer) = 100 bytes
   
   Sin embargo, el número real de bytes leídos puede ser menor:
   - Si el archivo tiene menos de 100 bytes disponibles desde la posición actual
   - Si se alcanza EOF (End Of File) antes
   - Si ocurre un error
   
   La función read() retorna el número real de bytes leídos:
   ssize_t bytes_read = read(fd, buffer, sizeof(buffer));
   
   Casos:
   - bytes_read = 100: Se leyeron todos los bytes solicitados
   - 0 < bytes_read < 100: Se alcanzó EOF o había menos datos disponibles
   - bytes_read = 0: EOF alcanzado (no quedan datos)
   - bytes_read = -1: Error (consultar errno)


4. Dada la declaración:
   char *pmap = (char *)mmap(NULL, TAM, PROT_READ, MAP_PRIVATE, fd, 0);
   ¿Qué operación realiza esta llamada? ¿Qué significa NULL en el primer parámetro?
   -------------------------------------------------------------------------------
   
   RESPUESTA: 
   
   OPERACIÓN: Mapea el contenido de un archivo en la memoria del proceso.
   
   Memory mapping permite acceder al contenido de un archivo como si fuera un 
   array en memoria, sin usar read/write explícitamente.
   
   Parámetros:
   - NULL: Permite al SO elegir la dirección de memoria para el mapeo
   - TAM: Tamaño en bytes del mapeo
   - PROT_READ: Protección de solo lectura
   - MAP_PRIVATE: Cambios no se escriben en el archivo (copy-on-write)
   - fd: Descriptor del archivo a mapear
   - 0: Offset desde el inicio del archivo (comienza en byte 0)
   
   NULL en el primer parámetro:
   Significa que el sistema operativo decide automáticamente dónde ubicar el 
   mapeo en el espacio de direcciones del proceso. Si se especificara una 
   dirección concreta, se intentaría mapear en esa dirección (sujeto a 
   restricciones de alineación y disponibilidad).
   
   Uso:
   pmap[0], pmap[1], ... acceden a los bytes del archivo como array.
   
   Ventajas:
   - Acceso más rápido que read/write
   - El SO gestiona automáticamente la carga/descarga de páginas
   - Compartición eficiente de memoria entre procesos


5. En FAT32, ¿qué significa que el primer octeto del nombre de una entrada 
   de directorio tenga el valor 0xE5?
   ------------------------------------------------------------------------
   
   RESPUESTA: El archivo ha sido BORRADO (deleted)
   
   Cuando se elimina un archivo en FAT32:
   - NO se borra físicamente su contenido del disco
   - NO se elimina completamente su entrada en el directorio
   - Se marca como borrado cambiando el primer byte del nombre a 0xE5
   
   Implicaciones:
   1. La entrada puede ser reutilizada para nuevos archivos
   2. Los datos siguen en el disco hasta que se sobrescriban
   3. Es posible recuperar archivos borrados (como en la Fase 3)
   4. Los programas de listado de directorios ignoran estas entradas
   
   Código en fatsoa.c:
   if (directory_info[i].DIR_name[0] != (uint8_t)0xe5)
   {
       // Mostrar solo si NO está borrado
   }
   
   Este mecanismo es fundamental para:
   - Herramientas de recuperación de archivos
   - Análisis forense digital
   - Borrado rápido de archivos (solo se cambia 1 byte)


6. ¿En qué número de cluster se encuentra el directorio raíz "/"?
   --------------------------------------------------------------
   
   RESPUESTA: Cluster 2
   
   En FAT32, el directorio raíz se ubica en el cluster especificado por el 
   campo BPB_RootClus del Boot Sector, que típicamente es 2.
   
   Clusters reservados:
   - Cluster 0: No se usa (reservado)
   - Cluster 1: No se usa (reservado)
   - Cluster 2: Primer cluster de datos (normalmente directorio raíz)
   
   Diferencia con FAT12/FAT16:
   En FAT12 y FAT16, el directorio raíz tiene una ubicación fija entre la FAT 
   y la zona de datos, con tamaño limitado. En FAT32, el directorio raíz es 
   un directorio normal que puede crecer dinámicamente.
   
   Verificación en fatsoa.fs:
   - Boot Sector offset 0x2C: BPB_RootClus = 0x00000002
   - Directorio raíz offset: 0x36000 (calculado para cluster 2)


7. Si el número de sectores por cluster es 8, ¿cuál es el tamaño en 
   octetos de un cluster?
   -----------------------------------------------------------------
   
   RESPUESTA: 4096 bytes (4 KB)
   
   Fórmula:
   Tamaño cluster = Sectores por cluster × Bytes por sector
   Tamaño cluster = 8 × 512 = 4096 bytes
   
   Para fatsoa.fs:
   - BPB_BytsPerSec (offset 0x0B): 512 bytes
   - BPB_SecPerClus (offset 0x0D): 8 sectores
   - Tamaño de cluster: 8 × 512 = 4096 bytes = 4 KB
   
   Importancia:
   El cluster es la unidad mínima de asignación. Un archivo de 1 byte 
   ocupa 1 cluster completo (4096 bytes en disco), desperdiciando el resto.
   
   Trade-offs del tamaño de cluster:
   - Clusters grandes: Mayor desperdicio de espacio (fragmentación interna)
   - Clusters pequeños: Más entradas en la FAT, mayor fragmentación externa


8. Si el número de sectores reservados es 32, ¿cuál es el desplazamiento 
   desde el comienzo de la imagen donde comienza la FAT?
   ---------------------------------------------------------------------
   
   RESPUESTA: 16384 bytes = 0x4000
   
   Fórmula:
   Offset FAT = Sectores reservados × Bytes por sector
   Offset FAT = 32 × 512 = 16384 bytes = 0x4000
   
   Para fatsoa.fs:
   - BPB_RsvdSecCnt (offset 0x0E): 32 sectores
   - BPB_BytsPerSec: 512 bytes
   - FAT begin offset: 32 × 512 = 0x4000
   
   Sectores reservados incluyen:
   - Sector 0: Boot Sector
   - Sector 1: FSInfo (normalmente)
   - Sectores 2-31: Reservados / Backup Boot Sector
   
   Estructura del volumen:
   [Sectores Reservados][FAT #1][FAT #2][Zona de Clusters]
   [   0x0 - 0x3FFF  ][0x4000-...][...][0x36000-...]
   
   Verificación:
   $ hexdump -C -n 16 -s 0x4000 fatsoa.fs
   Debe mostrar las primeras entradas de la FAT.


9. ¿Cuál es el desplazamiento desde el comienzo de la imagen donde 
   comienza la zona de clusters?
   ----------------------------------------------------------------
   
   RESPUESTA: 221184 bytes = 0x36000
   
   Fórmula:
   Offset clusters = (Sectores reservados + Número FATs × Sectores por FAT) × Bytes por sector
   
   Para fatsoa.fs:
   - Sectores reservados: 32
   - Número de FATs: 2
   - Sectores por FAT (BPB_FATSz32): 200
   - Bytes por sector: 512
   
   Cálculo:
   Offset = (32 + 2 × 200) × 512
   Offset = (32 + 400) × 512
   Offset = 432 × 512
   Offset = 221184 bytes = 0x36000
   
   Estructura completa:
   0x00000 - 0x03FFF: Sectores reservados (32 sectores = 16384 bytes)
   0x04000 - 0x1BFFF: FAT #1 (200 sectores = 102400 bytes)
   0x1C000 - 0x35FFF: FAT #2 (200 sectores = 102400 bytes)
   0x36000 - ...    : Zona de clusters (datos)
   
   El cluster 2 comienza en 0x36000.
   
   Fórmula para cualquier cluster N:
   Offset(N) = ((N - 2) × Sectores/Cluster × Bytes/Sector) + 0x36000


10. ¿Qué significa que una entrada de la FAT tenga un valor 0x0FFFFFF7?
    -------------------------------------------------------------------
    
    RESPUESTA: El cluster está marcado como ERRÓNEO (bad cluster)
    
    Significado:
    - El cluster tiene sectores defectuosos físicamente
    - No debe usarse para almacenar datos
    - Es una marca permanente que indica error de hardware
    - El sistema operativo no asignará este cluster a ningún archivo
    
    Valores especiales en FAT32 (28 bits efectivos):
    - 0x00000000: Cluster libre (disponible)
    - 0x00000002 - 0x0FFFFFEF: Número del siguiente cluster en la cadena
    - 0x0FFFFFF0 - 0x0FFFFFF6: Reservado
    - 0x0FFFFFF7: Cluster erróneo (bad cluster / bad sector)
    - 0x0FFFFFF8 - 0x0FFFFFFF: End of Chain (EOC - último cluster del archivo)
    
    En la Fase 3 de la práctica:
    Los clusters 7 en adelante están marcados como 0x0FFFFFF7 para ocultar 
    un archivo PDF borrado. Esta es una técnica de ocultación de datos que 
    aprovecha que el sistema operativo normalmente no accede a clusters 
    marcados como erróneos.
    
    Verificación en fatsoa.fs:
    $ hexdump -C -n 4 -s $((0x4000 + 7*4)) fatsoa.fs
    Offset 0x401C: 0xF7 0xFF 0xFF 0x0F (0x0FFFFFF7 en little-endian)
    
    Recuperación:
    El programa recuperar_pdf.c lee estos clusters "erróneos" para extraer 
    el archivo PDF oculto (_DS.pdf).
